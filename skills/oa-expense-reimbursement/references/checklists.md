# 按需使用的核对清单

## 票据清单

在当前受控工作区维护最小必要记录，勿加入共享技能包。建议字段：

| 项目 | 用途 |
| --- | --- |
| 本地材料编号、原始文件 | 定位原件，避免把多个格式当成多张票 |
| 费用日期/期间、业务事由、费用类别 | 对应明细行；不同于单纯开票日期 |
| 发票号、开票日期、金额、抬头、商户 | 核对真正在本次报销范围内的发票 |
| 付款/订单/行程文件 | 匹配金额、日期、路线等；不一致需解释 |
| 关联申请及匹配依据 | 记录出差、公车申请，避免仅按标题选中 |
| 重复、退款、取消、红冲、重开状态 | 防止重复或无效费用入账 |
| 拟报金额、OA 明细行、处理状态 | 对账；区分票面金额和允许报销额 |

- 以原文件内容为准；OCR 不清的金额、时刻、日期需回看原图。无法读清时索要清晰原件，不猜。
- 官方邮件、转发邮件和重复下载可能是同一票。可用文件哈希识别完全相同的文件，再用发票标识检查不同文件/格式中的同一票。
- PDF、OFD、XML 是同张发票的不同载体时只计算一次金额；是否保留全部原格式取决于企业要求。
- 邮件搜索结合发送方、主题、时间、金额相关词及官方/转发版本。记录实际检索范围，不将搜索无结果表述成“没有收到”。
- 历史报销总额或少量记录只可用于初筛，不代表完成逐票查重。请本人核实尚未覆盖的历史报销、退款、红冲或重开情况。

## 字段映射

首次使用某个 OA 时记录“页面字段 → 本次依据 → 实际选项/值 → 是否必填 → 是否可编辑”，只保存在本次工作区。稳定信息需要复用时另获本人同意，并与可分享技能分离。

特别检查：
- 科目按企业制度选择；不要把网约车固定归入城际交通，也不要把所有铁路票据固定归入某个税务类型。
- 发票性质按实际票据与下拉选项判定。普通发票、专用发票、收据不能只按是否电子文件判断。
- 星号不等于可手填。冲抵、实付等金额可能来自计算或其他字段，先查来源。
- 费用行合计、票据拟报合计与表头总额一致；差异应有明确依据。
- 收款账户属于当前报销人，并通过安全方式核对；面向用户的摘要仅展示必要脱敏信息。

## 附件检查

1. 先列真实文件路径和大小，再按清单收集，不手工猜测长文件名。
2. 每项费用能找到发票及必要的付款、订单或行程材料；缺件单独列出。
3. 去掉完全相同的重复文件，保留具有不同证明作用的材料。附件数量与发票数量分别统计，不将文件数当成费用笔数。
4. 检查 OA 允许的类型、单文件/总大小、压缩包规则。若不允许 ZIP，说明限制并按授权改用支持的上传方式。
5. 合包时避免同名覆盖、绝对路径和多余私人材料。查看压缩包成员，执行完整性检查，确认数量和文件大小；可通过哈希验证跨环境传输前后相同。
6. 使用已支持的安全文件传输通道，不把下载凭据或私密地址写到共享说明中。
7. 上传后核实附件名称/数量/大小与完成状态，保存并重开确认。若工具结果不明确，先查是否已存在，避免重复上传。

## 最终核对摘要模板

- 单据：〈当前报销单标识/标题〉
- 报销人、公司/部门：〈本人已核对信息〉
- 费用范围与期间：〈范围〉
- 科目与拟报金额：〈逐项简表〉；合计：〈金额及币种〉
- 收款信息：〈必要脱敏信息〉
- 关联申请：〈类型及匹配依据〉
- 附件：〈发票份数、其他材料份数、打包或上传情况〉
- 查重范围、待解决事项：〈明确说明；无则写无〉
- 当前状态：〈已核实的状态〉

若请求代提交，询问：“请确认以上这张报销单及合计金额可以提交。”不要将查看摘要、保存草稿或单纯认可流程视为最终提交授权。
