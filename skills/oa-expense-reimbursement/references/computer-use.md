# 电脑操作与任务记录

## 首次准备

1. 读取员工私有配置；缺少时从 `assets/employee-profile.example.json` 复制到本人指定的私有目录。示例本身不能直接用于生产任务。
2. 核对员工身份、公司、部门、实际邮箱/OA 登录身份、规则和材料目录。账号名称可用非敏感提示帮助核对；密码、验证码、令牌、cookie、下载签名链接和银行账号不进入配置或任务记录。
3. 检查实际可用控制工具及权限。按当前工具提供的文档使用，不根据技能名称推断已连接。没有业务 API 时可使用获准的网页；不能控制目标桌面时说明缺少哪项能力。
4. 检查 Python 3.10+ 和状态助手能否运行。任务数据目录必须是绝对路径、位于 Git 工作树/共享技能目录之外；使用员工自己的非共享数据位置。
5. 首笔任务由本人核对当前表单字段、费用口径、附件和关联要求。模板或制度变化后重新校准相关部分。不要用已过期截图或他人的表单值当默认值。

## 选择操作方式

- 用 Gmail 连接搜索邮件并读正文及支持的附件。连接返回不支持的材料时，先查找已下载或用户已提供的原件，再处理实际缺项。通过邮件链接进入站外发票服务时，使用已连接 Chrome 插件。
- 在 Chrome 的已登录 OA 会话核对和填写。站外 PDF 预览、下载成功、OA 附件栏出现及保存后附件留存是四个不同状态，逐项核实。下载压缩包时在私有目录核对成员；页面保存能力不可用时记录具体缺件。
- 依据当前上传控件调用 Chrome 插件文档里的文件选择器。若插件提示缺少本地文件访问，确认浏览器扩展的“允许访问文件网址”，只在确实缺少时请本人开启。先用一个短文件验证，再批量上传遗漏的原件，确认上传弹窗并复查附件栏。
- 用户明确要求只用 Chrome 时保持该操作方式。只有本人允许且确实需要操作桌面客户端时，用 Computer Use 贯通该步骤。
- 固定坐标不是持久定位依据，截图也不是完整材料清单。不要通过隐藏接口、页面内部状态修改或未授权脚本绕过正常校验。
- 在实际登录的浏览器会话内工作。不得复用别人的 cookie、登录会话或银行信息。
- Windows 原生桌面控制使用活动前台。本人操作时暂停；云电脑优先在该环境内运行控制能力。窗口缩放、远程连接、锁屏等变化后重新检查。只有实测成功才可说明断开后仍能工作。
- OA 报“数据已被刷新，请重新打开”或保存结果不明时，先核对原单实际留存，再从待发列表或最后验证的原单完整入口重新进入。同一报销只在一个页面编辑；往期单用只读详情。先核验上次保存结果再补写，避免重建单据、重复上传或重复发送。
- 选公司、部门及联动下拉时逐个确认值与编码。组织树若有“选择”按钮，先把目标移入已选区再确认。日期控件聚焦后可能更换输入元素；重新定位当前可见控件，失焦和保存重开后复核。

## 私有配置与记录

`assets/employee-profile.example.json` 只说明字段结构，由技能读取，不会自动替员工登录或授予提交权限。

- `employee_id`：本机记录使用的小写非敏感别名，不使用身份证号、邮箱密码或银行卡。
- `organization`、`department`、`identity_hint`：辅助核对；每次仍以当前页面身份为准。
- `oa_url`、`mailbox_url`：员工实际授权的入口，只存本人私有配置，不回写公共仓库。
- `execution_environment`：记录在哪个本机/云电脑会话执行，不能据此推断连接已通。
- `private_data_root`：员工私有记录绝对目录，必须在 Git 工作树和共享技能之外；每位员工选自己的目录。
- `company_rules_file`、`field_map_file`：本地已核对制度/字段映射的位置，没有材料时保持空值并查明，不能编造。

将本次范围、材料清单、字段依据、匹配结果、任务日志和必要截图保存在该私有环境。共享技能只保存通用规则。截图或附件不应包含无关邮件和其他员工资料。公开同步前检查文件列表。

## 状态助手命令

下面的占位符由真实私有路径、非敏感员工别名和本次任务 ID 替换。任务 ID 不重复，恢复同一笔时使用原 ID。路径含空格时保留引号。命令在当前控制环境的合法文件/命令工具中运行，不通过电脑操作控制 Codex 自身或终端来绕过限制。

通用前缀：

```text
python "<技能目录>/scripts/task_state.py" --root "<私有记录绝对目录>" --employee "staff-a" --task "expense-20261115-a"
```

在前缀后追加下列子命令：

| 节点 | 子命令与所需事实 |
| --- | --- |
| 开始或恢复 | `init --intent draft` 或 `init --intent submit`；随后 `show`，核对 OA 真实状态 |
| 材料已核对 | `checkpoint --stage materials --evidence "<私有材料清单或实际核验记录>"` |
| 草稿保存并重开核对 | `checkpoint --stage draft --evidence "<草稿标识与实际核验记录>"` |
| 本人改变本次意图 | `set-intent --intent submit --authorization "<本次明确授权出处>"`；保留同一任务 |
| 提交前 | `begin-submit --document-id "<实际草稿标识>" --amount "<已核对总额>" --currency "CNY" --authorization "<本次有效授权出处>" --evidence "<最终核对记录>"` |
| 确认提交成功 | `record-result --outcome submitted --oa-number "<真实申请单号>" --evidence "<OA状态核验证据>"` |
| 提交结果未知 | `record-result --outcome unknown --evidence "<超时或断线的实际观察>"` |
| 已查证确实未提交 | `record-result --outcome not-submitted --evidence "<能够证明未提交的OA核验记录>"` |
| 普通步骤失败 | `block --reason "<具体错误及待处理事项>"` |

### 执行约束

- `init` 必须恢复已有任务，不能清空或偷偷改变原意图；本人明确改变意图时使用 `set-intent`。
- `begin-submit` 要求提交模式、已核对草稿、明确金额/币种和授权/证据。它先把状态写成提交进行中；成功返回后才允许实际点击。
- 任何已有提交中、结果未知或已提交状态，都不能再次进入提交步骤、改意图或用普通检查点覆盖。普通 `block` 也不能解除这项约束。
- 提交进行中或结果未知时，先核对 OA 原单据及已发列表。搜索无结果、页面超时或没看到成功提示不能证明未提交；证据不足时保持未知。
- 确认未提交后，可以在同一任务继续核验和重试；实际材料/金额变化时重新读取、核对授权范围和保存草稿。
- 普通阻碍处理完后，以真实证据执行同阶段或后续阶段的检查点恢复；不得伪造证据或将阶段倒退以掩盖失败。
- 单个员工的同一任务只由一个执行者操作。助手的文件锁保护本地状态写入，不能替代页面操作的协调或跨设备查重。
- 证据参数是私有文件路径或可追溯的观察/用户授权出处，不是已验证事实的自动认证。脚本不联网，不验证邮箱、OA 或授权真实性；技能必须先观察再记录。
- 如果保存状态失败，立即报告，不能继续提交后再补记。退出码成功只表示该记录操作成功。

## 任务节点与 hook 的区别

本技能要求：开工读记录，关键步骤成功后存档，失败立即记录与三句话报告。状态助手执行真实本地读写和提交状态检查。

这不表示 Codex 原生生命周期 hook 已安装，也不保证宿主在任意崩溃时仍能执行回调。恢复依赖最近一次成功记录；提交前的持久状态使中断后不会按正常路径再提交一次。若今后安装原生 hook，应单独核验当前版本的事件接口和安装结果，不能只写一句提示词就宣称已接入。

## 小范围试点验收

先本人一笔，再一名员工用自己的账号完成一笔。观察下面各项：

1. 能控制实际邮箱与 OA 所在的桌面；原件可下载并核对。
2. 员工、公司、费用范围、金额、附件和关联均正确。
3. 草稿保存后重开仍保留正确内容。
4. 按本次有效授权完成提交，取得真实申请单号和状态。
5. 中途停止后从原任务继续，已处理材料和已建草稿不会重复创建。
6. 模拟“提交后未收到响应”时保持未知并先查 OA，不能直接重发。
7. 第二名员工看不到第一名员工的私有材料，使用自己的登录和配置。

离线测试只覆盖本地记录助手；不证明电脑控制连接、页面适配、真实提交、审批或付款已经成功。未完成的验收项如实保留。
